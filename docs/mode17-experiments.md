## C8 采样分片的复核范围

候选使用 vLLM V2 runner 的 `--enable-batch-sharded-sampling`。各 GPU 计算自身词表部分，经 AllToAll 把请求词表交给各自的采样 owner。owner 继续运行原 top-p、grammar、logprobs 和拒绝采样逻辑。目标与 DSpark 草稿都执行请求分片。C8 沿用 `burst8late` 的调度规则。两者分别负责采样与调度。

A/B 的两组 C8 32K 同时在 decode 的吞吐为 818.28 → 836.94、792.77 → 838.30 tok/s，输出各 768 token。延迟样本包含不同请求陆续进入 decode 的阶段。两档各八条检索、logprobs 与工具调用检查通过，采样文本哈希有差异，既往同档跨进程采样也观察到波动。小包 IPC 的独立对照在 8 行为 13.62 → 10.01 µs，说明固定 IPC 选型对拆出采样净收益有必要。合并试运行另通过 128K 冷检索、八路混合功能检查和八路各 512 token 生成。档 17 生产采样沿用档 16。
