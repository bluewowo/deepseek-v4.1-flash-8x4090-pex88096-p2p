# DeepSeek V4.1 Flash 1017 on 8× RTX 4090 48 GB with PEX88096 and PCIe P2P

This profile adds a P2P-enabled deployment to the original 8-GPU wrapper. It pins the model and runtime, applies three SM89 patches in a separate source overlay, and includes a cold-prefix benchmark. The profile can be run from a shell and binds to localhost by default.

## 硬件与版本

- Linux x86-64、八张 48 GB RTX 4090（SM89）、CUDA Toolkit 13.0、Python 3.12 和 uv。启用 P2P 的驱动与固件已在主机上安装。实测环境为 Ubuntu 24.04、Linux 6.17 和 NVIDIA 595.71.05。
- 实测驱动是 [Duanyll 595.71.05-p2p-48g](https://github.com/Duanyll/open-gpu-kernel-modules/releases/tag/v595.71.05-p2p-48g)，算力解锁工具是 [gpu-unlock-ada v1.1.1](https://github.com/JustAResearcher/gpu-unlock-ada/releases/tag/v1.1.1)。两者由各自项目分发，按各自文档准备。此 profile 仅配置推理服务和 GPU 通信。
- 固定的 [1017 快照](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash-1017/tree/1bae0e1088993b9b82de08f59de5be5a34e42170) 有 48 个权重分片，约 475 GiB。另给 Python、编译缓存、模型加载和页缓存预留空间。Engram 的两张表在 TP8 下合计约 189 GiB pinned 主机内存，实测主机有 2 TiB RAM。
- [vLLM Vision14 发布](https://github.com/yhfgyyf/vllm-deepseek-v4-sm89/releases/tag/v0.33.0-vision14-sm89-sm120-cu130) 提供安装脚本默认下载的 vLLM 和 FlashInfer Vision4 post1。vLLM wheel 摘要与生产实测一致，生产跑分使用原版 FlashInfer Vision4。发布资产、两种 FlashInfer 的摘要和版本约束分别见 [安装脚本](../setup_pex88096.sh) 与 [依赖约束](../profiles/pex88096-constraints.txt)。

## 从空环境安装

在项目目录内执行。需要使用其他 Python 包镜像时，可设置 `PYPI_INDEX_URL` 和 `PYTORCH_INDEX_URL`。vLLM wheel 和 FlashInfer wheel 也可放入 `wheels/` 或使用 `WHEEL_DIR` 指定目录。安装脚本总是核对 wheel 的 SHA256，并把生产补丁应用到独立 overlay。

```bash
./setup_pex88096.sh
cp profiles/pex88096.env.example .env.pex88096

model="$PWD/models/DeepSeek-V4.1-Flash-1017"
uvx --from huggingface-hub hf download deepseek-ai/DeepSeek-V4.1-Flash-1017 \
  --revision 1bae0e1088993b9b82de08f59de5be5a34e42170 \
  --local-dir "$model"
./tools/verify-model.sh "$model"
(cd "$model" && sha256sum -c ../../profiles/1017-metadata.sha256)
# 完整校验需读取全部权重
(cd "$model" && sha256sum -c ../../profiles/1017-weights.sha256)
```

公开的 post1 已使用已缓存的依赖，在空 venv 验证安装、overlay 导入、补丁摘要和启动 dry-run。与原版相比，wheel 的运行文件差异集中在构建元数据和三份 SM89 sparse MLA 兼容头文件。下方八卡吞吐数据来自原版 Vision4。

已有相同摘要的原版 FlashInfer Vision4 时，可以用 `FLASHINFER_VARIANT=original ./setup_pex88096.sh` 恢复实测软件组合。依赖检查应显示 CUDA runtime 13.0。编译工具链需提供 nvcc 和可用于链接的 `libcudart.so`。环境和 overlay 位于 `.venv-pex88096/` 和 `overlays/pex88096-vision14/`，可与上游默认部署并存。

## 识别双交换芯片与验证 P2P

```bash
./tools/check-host.sh
lspci -tv
```

本机两组分别是 GPU `2,3,4,5` 和 GPU `0,1,6,7`，rank 顺序为 `2,3,4,5,0,1,6,7`。用 `nvidia-smi topo -m`、PCI 树和 GPU bus ID 对照你自己的设备，修改 `.env.pex88096`。同为 PXB 的 GPU 对也可能经过不同交换芯片。在 `nvidia-smi topo -p2p r` 与 `nvidia-smi topo -p2p w` 中核对预期可达的设备对。实测两张矩阵均有 56 个非对角项为 OK。

该配置用 `NCCL_P2P_LEVEL=SYS` 和 `NCCL_P2P_DISABLE=0`，并启用 FlashInfer PCIe IPC 小消息归约。模型与 draft 都是 TP8，专家并行覆盖八卡，只有一个流水线阶段。按交换芯片排列 rank 仍然是一个 TP8 组。8K 大块预填充的归约仍可走 NCCL。实际通信路径用启动日志中的 `via P2P/CUMEM` 与 IPC 初始化记录确认。

## 手动启动和校验

如 GPU 顺序、通信网卡、CUDA Toolkit 或模型目录与示例不同，先改 `.env.pex88096`。在独占八卡时运行下列命令。启动后在运行服务的终端按 Ctrl+C 停止。

```bash
DRY_RUN=1 ./launch_pex88096.sh
NCCL_DEBUG=INFO NCCL_DEBUG_SUBSYS=INIT,ENV,GRAPH ./launch_pex88096.sh
```

另开一个终端。

```bash
curl --fail --noproxy '*' http://127.0.0.1:8011/health
curl --fail --noproxy '*' http://127.0.0.1:8011/v1/models
ENV_FILE="$PWD/.env.pex88096" ./tools/smoke-test.sh
```

默认配置为 1,048,576 总 token 窗口（含输出）、8192 batched tokens、最多 4 路、0.96 显存配额、FP8 KV、CED、DSpark K7 自适应验证、`FULL_AND_PIECEWISE` CUDA Graph。实测 KV 池 3,522,266 token，按启动日志估算可容纳约 3.36 个满窗请求。实际满窗并发受请求长度和可用 KV 影响。

## 三处生产修改

1. **Prefill 索引查询行分片**。对长上下文的 native MXFP4 indexer，把原先各卡重复执行的查询行分给八卡。每行仍扫描原范围，最后汇合整数 Top-K。现有工作区上限仍用于控制本卡的打分块。
2. **Decode 索引查询行分片**。对满足展平、至少 4 验证行和索引宽度门槛的原生全历史打分路径，分摊查询行并汇合整数索引与下游候选块。合成数据的 logits 逐元素一致。现有 Top-K 对并列位置及元素顺序可能返回不同结果，整模型生成未建立逐 token 等价。
3. **Ada 预填充 GEMM tile**。对一组已测的 8192 行 MXFP8 线性投影使用 128×64 tile，保留原 K32 量化与缩放流程。

当前 profile 合入上述三项。WO FP8 交换、上游 paired SWA 和 `wo_b` 量化融合属于独立实验，生产对照仍以三补丁组合为准。解码行分片借鉴了 Spark 项目的查询行分摊方法，保留本模型在 Ada 上已有的 MXFP4 与候选块路径。

## 单流实测

以下为脱敏后的合成检索卷。每档两个输入 seed，单并发、384 个输出 token、零前缀命中。prefill 和输出速度按 vLLM 的请求阶段计时，TTFT 按客户端计时。输出速度会随 DSpark 接受长度变化。

| 输入约 | 冷 prefill（tok/s） | TTFT（s） | Decode（ms/验证轮） | 输出（tok/s） |
| --- | ---: | ---: | ---: | ---: |
| 8K | 10,305 | 0.853 | 14.85 | 191.5 |
| 128K | 11,924 | 11.488 | 14.80 | 173.3 |
| 512K | 10,712 | 50.980 | 15.74 | 211.6 |

同系列的前一档，采用相同预填充补丁，在 1,047,532 个真实输入 token 下完成 384 个输出，三处检索码均正确。服务端冷 prefill 112.44 秒，约 9,317 tok/s。该历史样本使用当时的 decode 路径。上表和近满窗样本都使用原版 FlashInfer Vision4。

前台服务空闲时可以复跑。每轮用新的 cache salt，运行中避免其它请求污染 vLLM 指标增量。模型使用自定义目录时，给脚本传 `--model-dir`。

```bash
.venv-pex88096/bin/python tools/benchmark-pex88096.py \
  --retrieve --require-cold --cache-salt "warm-$(date +%s%N)" 32768
.venv-pex88096/bin/python tools/benchmark-pex88096.py \
  --output 384 --seed 1017 --repeats 2 --require-cold \
  --cache-salt "cold-$(date +%s%N)" 8192 131072 524288
```
